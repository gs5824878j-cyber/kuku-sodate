# 九九：端末・ブラウザ別の手動確認

実際の利用者のJSONを提出・アップロードしない。合成記録または本人の端末内だけで確認する。本番切り替え承認前は旧URLと記録を残す。

| パターン | 保存/共有と復元の条件 | 現在の実機確認 |
|---|---|---|
| PCの利用ブラウザ | 同じプロファイルで旧記録を保存→別originの確認サイトへ復元→学習・育成の表示比較 | 利用者のPC実記録で表示一致。ブラウザ名は未確認 |
| Chrome / Edge / Firefox | 記録なし/あり、JSON保存・選択、同じファイルの再選択、拒否/中止、他タブ更新 | Chromiumのみ自動試験済み。Edge/Firefox実機は未確認 |
| Androidブラウザ | ダウンロードとファイル選択、対応時は共有、テキスト代替 | 実機未確認 |
| Androidホーム画面版 | 元のアイコンから起動し、画面内の保存欄で元記録が読める→保存→別origin復元 | 実機未確認 |
| iPhone/iPad Safari | JSON保存、共有→ファイルに保存、ファイル選択、再起動後の記録確認 | 実機未確認 |
| iPhone/iPadホーム画面版 | Safariから開き直さず元のアイコンから起動→画面内の保存欄→Filesへ保存→新サイト/新ホーム画面版で復元 | 実機未確認 |
| プライベート・複数プロファイル | 保存場所が異なることを案内。記録がある元の画面で個別に保存。閉じる前にファイルを確認 | 表示と保存拒否は自動試験、実機未確認 |
| 記録なし・消去済み・端末故障 | 別の端末の記録は自動取得できない。初期記録を救出記録として捏造しない | 保存専用画面の記録なし試験済み。消去済み記録は復旧保証なし |

各パターンで：

1. 学習済みの九九・ポイント・育成型/XP・設定を端末内で控える。
2. 旧アプリの「記録の保存・復元」を押し、別のブラウザへ移動しないことを確認する。
3. JSON保存を行い、ファイルの存在を確認する。共有非対応/中止時はテキスト全体を端末内へ保存する。
4. 別originへ移りファイルまたはテキストを読み込む。読み込みだけでは記録が変わらないことを確認する。
5. 既存記録がある場合、その記録も退避して確認後に復元する。中止時に既存記録が残ることを確認する。
6. 他の九九画面を閉じ、アプリを開き直して表示を比較する。ホーム画面版は再起動後も確認する。
7. 本番ドメインへ移行した後は、新origin/ホーム画面版で再度復元が必要。確認サイトの記録は自動では移らない。

Chromeのタッチ画面エミュレーションやデスクトップWebKitはiOS実機の保存領域・Files共有・ホーム画面版の合格に代用しない。
旧GitHubのブログ内に保存した記録についても、通常ブラウザの同origin救出と、別保存領域を持つ旧ホーム画面版を区別する。すでに転送される旧ブログ内の起動URLについて、全保存領域を救出できるとは保証しない。
